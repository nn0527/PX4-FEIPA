# 遥控脱离保持与失联保护核验

控制台入口wall_console_flight.launch设置hold_timeout_s=0（关闭按保持时长自动降落）、hold_require_explicit_detach=true。正常HOLD等待第二次CH12或同一操作入口的显式脱离请求；CH12回低只是准备下一次有效边沿。无请求、反馈正常时可以持续保持。旧台架默认保持看门狗仍可通过正hold_timeout_s启用。

HOLD期间指令心跳/业务意图失效，决策进入ABORT。模式管理器独立监测：HOLD状态或指令反馈过期、已看到detach pending但1秒内仍未进入DETACH、请求反馈在执行前消失，都锁存安全降落意图；即使决策状态反馈不可用，也能在新鲜连接、已解锁、OFFBOARD、急停clear时请求AUTO.LAND。它不伪造行为状态消息。收到新的实际AUTO.LAND反馈才算确认；通信断开时无法发送/确认模式，只能依靠PX4内部保护；急停和飞手切换模式保持优先权。

已进入DETACH后仍保留机构释放确认（若启用ACK）、20s分离超时、融合反馈与安全检查。当前实体机构输出和ACK均关闭，软件释放确认不证明实体机构已释放。重复、迟到或尚未允许的脱离脉冲不会排队到下一次保持，也不会仅因重复而触发降落。没有收到任何可观察的RC/业务请求时，程序不能推断飞手实际按过开关。

PX4失联动作等待参数COM_OF_LOSS_T目标改为2.0s；COM_OBL_RC_ACT仍为4（Land）。COM_OBL_ACT仅在固件适用时要求0。核验仍限飞控连接且未解锁，逐项读取，必要时设置，再独立读回匹配。/attachment/ceiling_failsafe_status发布目标、实际读回值、读回时间、已核验状态和原因；测试台显示这两个参数及核验结果。断连或反馈过期时不显示通过。

2.0s是PX4原生OFFBOARD指令流失联等待时间；核验节点的连接/源心跳有效期也改为2.0s，避免约1Hz心跳在1秒边界反复撤销核验。不是把全部ROS反馈新鲜度改为2.0s。飞控状态1.5s、运动反馈2s、急停0.35s等其他检查仍各自工作。

RECOVERY_HOVER用于下降达标后的制动、恢复稳定以及等待交回：以HOLD融合高度减0.50m为目标，通过高度误差生成竖直速度目标，再根据速度反馈调整推力。姿态稳定后锁定实测姿态，但高度推力闭环继续，因此下降过多会修正上升、偏高会修正下降。稳定条件需连续0.5s；首次15s未稳定仍ABORT；锁定后等待第三次CH12，不自动交回。

恢复阶段不以顶部雷达新鲜为高度门槛。高度与速度来自PX4融合里程计，要求里程计≤0.5s、估计器≤1.5s以及底部光流测距≤0.6s且质量/积分/距离有效。底部距离须>0且有限；顶部距离在上升/接触确认中要求有效且接收≤0.6s，当前配置量程0.03—40m，数字有效范围不等于真实硬件在所有环境的量程保证。
